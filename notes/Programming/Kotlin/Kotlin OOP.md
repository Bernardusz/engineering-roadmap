### 1. Constructor, Initialization & Properties
> So ever dreaded that Spring Boot code where you have to manually type out Bean type into the Constructor? In Kotlin, we don't need to do that 🐧

```kotlin
  
class Human (var name: String){  
    fun sayHello() {  
        println("Hello, $name!")  
    }  
}  
  
fun main() {  
    val human = Human("Kotlin")  
    human.name = "Java" // Automatically calls the setter generated for var  
    println(human.name) // Automatically calls the getter generated by the compiler  
    human.sayHello() // Calls a method  
}
```

In Java, we follows a strict convention: The Least Previlage Principle. So basically, even if you only need this to be public, make it private, and create getters and setters.

Kotlin changed this, by adding automatic getters and setters generator, so your code look pristine.

And if you say you need to add a verification for getter and setter, you can absolutely add that without breaking existing code.

```kotlin
class Human (name: String){ // Parameter for name  
    var name: String  
        set(value) {  
            name = value  
        }  
        get() {  
            return name  
        }  
    fun sayHello() {  
        println("Hello, $name!")  
    }  
}  
  
fun main() {  
    val human = Human("Kotlin")  
    human.name = "Java" // Automatically calls the setter generated for var  
    println(human.name) // Automatically calls the getter generated by the compiler  
    human.sayHello() // Calls a method  
}
```

Good feature indeed 🐧🐧

### 2. Default Acess Modifier
> By default in Java classes and methods are open for inheritance and package-private by default. In Kotlin, it is inversed. 

As sid in [[Null Safety & Types]] Kotlin, classes and methods are final and public by default, and there's no Package-private, only [[Null Safety & Types |Internal]]. 

This is done to enforce "Design for inheritance or else prohibit it" principle to prevent accidental subclassing bugs.

### 3. Special Structures
> Remember, Kotlin must be interoptable with existing Java code via Kotlin/JVM. That is why Kotlin adds features and class structures/types, not modifying things internally.

#### `data class` vs `records`
> In Java we have records for holding immutable data. In Kotlin we have data class.

```kotlin
@JvmRecord  
data class UserRecord(val name: String)  
  
data class User(val name: String)  
  
fun main() {  
    val userRecord = UserRecord("John Doe")  
    val user = User("John Doe")  
  
    userRecord.copy(name = user.name)  
    println(userRecord.equals(user))  
}
```

```bash
false
```

So Data class is a class that holds data, exactly like record, but you can make it immutable, though it is not recomeneded.

In Kotlin we do not have a `record` keyword. So to make sure things compile down to Java Record, we use annotation: `@JvmRecord`

#### Sealed Class & Sealed Interface
> So, we're covering this topic about [[Null Safety & Types | Sealed class]] again, because, actually, sealed class is Abstract and Public by default. The on e that is private is the constructor

```kotlin
package io.github.bernardusz  
  
@JvmRecord  
data class UserRecord(val name: String)  
  
sealed class User(val name: String)  
  
class UserImpl(name: String) : User(name)  
  
fun main() {  
    val user = UserImpl("John Doe")  
  
    println(user.name)  
}
```

```kotlin

```

How ever, the subclasses of a sealed class are restricted to the same package. The reasoning is exhaustive branching. So if during compile time, we have already put everything inside an if/is branch, we don't need else.

```kotlin
package io.github.bernardusz  
  
sealed class UiState(){  
    data object Loading: UiState()  
    data class Sucess(val data: String): UiState()  
    data class Error(val data: String): UiState()  
}  
  
//class UiStateImpl(name: String) : UiState() Commented to remove this option  
  
fun handleState(state: UiState){  
    when(state){  
        is UiState.Loading -> println("Loading...")  
        is UiState.Sucess -> println("Sucess: ${state.data}")  
        is UiState.Error -> println("Error: ${state.data}")  
    }  
}  
  
fun main() {  
  
}
```

So for sealed interface is the same as sealed class, but it can't hold backing fields, only abstract/accessor properties.

```kotlin
sealed interface ErrorState
sealed interface NetworkEvent

// This class belongs to BOTH hierarchies!
data class ConnectionTimeout(val url: String) : ErrorState, NetworkEvent

fun handleError(error: ErrorState) = when(error) {
    is ConnectionTimeout -> println("Failed to connect to ${error.url}")
}

fun handleNetwork(event: NetworkEvent) = when(event) {
    is ConnectionTimeout -> println("Retrying connection...")
}
```
